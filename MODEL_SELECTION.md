# Model selection

Why we picked the model that serves predictions, and how a new model replaces it.

## Problem

Predict heart disease (1 = disease, 0 = healthy) from 13 clinical features
(UCI Cleveland dataset, 303 rows, ~46% positive). The costly error is a **missed
sick patient**, so recall matters most, then F1.

## Candidates

| Model | Why it is a candidate |
|---|---|
| Logistic Regression | Simple, fast, small, easy to explain; strong baseline on small tabular data |
| Random Forest | Non-linear, handles feature interactions |
| Gradient Boosting | Often the strongest tabular model, but sensitive on small data |

All three share the same preprocessing pipeline (impute, scale, one-hot) and
the same stratified 80/20 split (seed 42): 242 train rows, 61 test rows.

## How the winner is chosen

1. Each model is scored with **5-fold cross-validation on the train set only** (CV F1).
2. Models whose **p95 single-row latency exceeds the budget (50 ms)** are excluded.
3. The highest CV F1 wins. The test set plays no part in the choice, so it stays an
   honest final check.
4. The winner must pass the **promotion gate** on the test set: accuracy >= 0.80,
   F1 >= 0.80, recall >= 0.80, p95 <= 50 ms.
5. It is promoted to `@champion` only if its test F1 beats the current champion.
   Otherwise the champion is kept.

## Results

Full table (generated by `python -m training.train`): `docs/model_comparison.md`.
It also reports F1 per data slice (sex, age < 55 / >= 55), p95 latency and model size.

First run (test set, 61 rows):

| Model | CV F1 | Test F1 | Recall | ROC-AUC |
|---|---|---|---|---|
| Logistic Regression | 0.801 | 0.867 | 0.929 | 0.958 |
| Random Forest | 0.779 | 0.900 | 0.964 | 0.943 |
| Gradient Boosting | 0.776 | 0.881 | 0.929 | 0.945 |

Slice F1, p95 latency and model size: copy them from `docs/model_comparison.md`
after your latest run.

## Decision

**Logistic Regression** has the best CV F1, so it is selected.

- Random Forest has a higher test F1, but the gap is about 2 patients out of 61.
  That is within noise. Picking by test score would leak the test set into the
  choice and make the reported number optimistic.
- Logistic Regression is the smallest and fastest model, which helps the latency
  budget and the container image, and its coefficients are easy to explain.
- With ~300 rows, simpler models are less likely to overfit.

## Limits

- The test set is small (61 rows) and the slices are smaller still. Slice F1 is
  indicative, not conclusive, and results move with the split seed.
- The dataset is one clinic's data, so performance on other populations is unknown.
- This is a course project, not a diagnostic tool.

## Changing the model

Rerun `python -m training.train` (or the training workflow). A new model replaces
the champion only if it passes the gate, beats the champion's F1 and stays inside the
latency budget. Update this file when the winner changes.
